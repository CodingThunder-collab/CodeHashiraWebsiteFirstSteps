Clean up LWC templates with lwc:if, lwc:elseif and lwc:else

Still stacking if:true and if:false templates to show a spinner, an error or your data? There's a cleaner way built into LWC.

TL;DR: Swap if:true / if:false for lwc:if, lwc:elseif and lwc:else. You get a real if / else-if / else chain, less nesting, and the directives Salesforce now recommends.

Before: nested if:true / if:false

A common pattern is loading → error → data. With the legacy directives you need two levels of nesting, and each condition is checked more than once. 

<template if:true={isLoading}>
    <lightning-spinner alternative-text="Loading"></lightning-spinner>
</template>
<template if:false={isLoading}>
    <template if:true={hasError}>
        <p>Something went wrong.</p>
    </template>
    <template if:false={hasError}>
        <c-account-list accounts={accounts}></c-account-list>
    </template>
</template>

After: one flat chain

<template lwc:if={isLoading}>
    <lightning-spinner alternative-text="Loading"></lightning-spinner>
</template>
<template lwc:elseif={hasError}>
    <p>Something went wrong.</p>
</template>
<template lwc:else>
    <c-account-list accounts={accounts}></c-account-list>
</template>

It reads top to bottom like JavaScript: the first true branch renders, and the rest are skipped.

Rules to remember

  • lwc:elseif and lwc:else must sit on the element directly after an lwc:if or lwc:elseif sibling.
  • lwc:else takes no value.
  • Don't mix lwc:if with if:true or if:false on the same element.
  • The directives work on <template> tags and on regular elements like <div>.
Hashira's note: Template conditions take a property, not an expression, so lwc:if={!isLoading} or lwc:if={count > 0} won't work. Put the logic in a getter instead: 
// accountPanel.js
get hasAccounts() {
    return this.accounts.length > 0;
}
<template lwc:if={hasAccounts}> ... </template>

Good to know

  • if:true and if:false still work, but Salesforce no longer recommends them and may remove them in a future release.
  • Migrating is safe to do one component at a time; nothing else in your code changes.
  • Reference: Render DOM Elements Conditionally in the LWC Developer Guide.
