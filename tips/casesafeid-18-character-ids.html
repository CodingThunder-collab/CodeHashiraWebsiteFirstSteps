Stop VLOOKUP mismatches with CASESAFEID()

Exported a report, ran a VLOOKUP in Excel, and got the wrong rows back? The culprit is usually the 15-character record ID.

TL;DR: Create a Text formula field with CASESAFEID(Id) and use it in your reports and exports instead of the standard 15-character ID.

The problem

Salesforce record IDs shown in the UI and in reports are 15 characters and case-sensitive. To Salesforce, these are two different records:

15-char ID18-char ID
001Hs00000AbCdE001Hs00000AbCdEIAV
001Hs00000abcde001Hs00000abcdeIAA

Excel's VLOOKUP and MATCH ignore case, so they treat both 15-character IDs as the same value and quietly return the wrong record.

The fix

The 18-character version adds a 3-character suffix that encodes the upper/lower case of the first 15 characters. That makes it unique even to case-insensitive tools.

  1. Go to Setup → Object Manager and pick your object (e.g. Account).
  2. Open Fields & Relationships → New.
  3. Choose Formula, label it 18 Digit Id, return type Text.
  4. Enter the formula below, set field-level security, and save.
CASESAFEID(Id)

Now add 18 Digit Id to your report and use that column for lookups.

Hashira's note: It works on lookup fields too — CASESAFEID(AccountId) on Contact gives you a case-safe parent ID for matching child rows to parent rows.

Good to know

  • The API, Data Loader and SOQL already return 18-character IDs.
  • Salesforce accepts both 15- and 18-character IDs in URLs and imports.
  • For a one-off export you can also paste the 15-character IDs into a case-safe converter, but the formula field is set-and-forget.
